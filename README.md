# chat-gzip

A chat interface for talking to a **gzip language model**—text generation via DEFLATE compression and beam search, inspired by [Language Modeling is Compression](https://arxiv.org/abs/2309.10668) and [Nathan Barry's gzipt](https://nathan.rs/posts/gzip-lm/).

> The only LLM with zero parameters and a 32 KiB context window.

## Stack

| Layer | Technology |
|-------|------------|
| Frontend | React 18, TypeScript, Vite, Tailwind CSS, [performative-ui](https://vorpus.github.io/performativeUI/) |
| Backend | Python 3, Flask |
| Deployment | Vercel (serverless Flask + static SPA) |
| Model | Vendored [gzipt](https://github.com/nathan-barry/gzipt) — zlib beam search, no neural weights |

This project follows the same Vite + Flask + Vercel pattern as [vibe-wordle](https://github.com/xboluna/vibe-wordle).

## Getting started

### Prerequisites

- Python 3.11+
- Node.js 24.x (matches Vercel `engines`)

### Backend (Flask)

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python run.py
```

API runs at `http://127.0.0.1:5000`.

### Frontend (Vite)

```bash
cd frontend
npm install
npm run dev
```

Dev server at `http://127.0.0.1:5173` — proxies `/api/*` to Flask.

### Production build (local)

```bash
npm run build
python run.py
```

Built assets land in `app/static/` and are served by Flask.

### Deploy (Vercel)

Connect the repo to Vercel. The root `package.json` build script compiles the frontend; `vercel.json` routes all traffic through `api/index.py`.

## API

| Method | Path | Description |
|--------|------|-------------|
| `GET` | `/api/health` | `{ "status": "ok" }` |
| `GET` | `/api/corpora` | Corpus catalog (`byte_length` per corpus) |
| `POST` | `/api/chat` | Generate assistant continuation |

### `POST /api/chat`

**Request:**

```json
{
  "corpus_id": "tiny-shakespeare",
  "temperature": 1.0,
  "max_bytes": 64,
  "messages": [
    { "role": "user", "content": "MENENIUS:\n" }
  ]
}
```

Messages are joined by newlines to form the gzip prompt. The last message must be from the user.

`temperature` is clamped to `[0.2, 2.0]` (0.2 = low / compressible, 2.0 = ludicrous). `max_bytes` is the generation byte budget, clamped to `[32, 512]`; generation halts on null bytes or when the budget is exhausted.

**Response:**

```json
{
  "content": "…generated bytes…",
  "meta": {
    "elapsed_ms": 980,
    "bytes_generated": 42,
    "corpus_id": "tiny-shakespeare",
    "temperature": 1.0,
    "max_bytes": 64,
    "context_bytes": 9,
    "context_limit_bytes": 32768
  }
}
```

Generation is capped by `max_bytes` per request (default 64 / snippet) with null-byte stop halting. Lengths at or above 512 bytes may time out.
